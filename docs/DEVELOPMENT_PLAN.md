최종 갱신: 2026-10-07 (Asia/Seoul)

상태: 준비 및 Phase 1~8 기능 구현 완료. 선택한 홈 1안/타임라인 A안의 Compose 디자인 적용. 실제 기기 시각 검증은 대기. 자동/에뮬레이터 검증 완료 범위와 개인 실기기 미검증 범위는 VERIFICATION.md에서 구분한다.

이 문서는 구현 범위와 완료 기준의 기준점이다. 실제 진행 상태는 [인수인계](SESSION_HANDOFF.md), 데이터 계약과 미결정 사항은 [개발 참고](DEVELOPMENT_NOTES.md), 제품 원칙은 [AGENTS.md](../AGENTS.md)를 따른다.

## 1. 개발 방향

생활 데이터를 안정적으로 저장한 뒤 저장 데이터 위에 화면과 분석을 얹는다. 가장 중요한 자산은 장기간 축적되는 LifeEvent다.

- Android 네이티브: Kotlin, Jetpack Compose, Room, Coroutine/Flow, WorkManager.
- 소스: Android Calendar Provider, NotificationListenerService, Health Connect.
- 초기에는 단일 app 모듈에서 UI, ViewModel, Repository, DataSource 및 Parser의 역할을 패키지로 구분한다.
- 데이터는 단말 내부에 저장한다. 서버 동기화, AI 의존 기능, embedding, vector DB, 범용 자동화는 MVP에 포함하지 않는다.
- 수집과 파싱을 분리하고 원본을 먼저 보존한다. 재수집과 재처리를 안전하게 반복할 수 있어야 한다.

```text
Calendar / Notification / Health Connect
                  ↓
          Collector / DataSource
                  ↓
             RawEvent Store
                  ↓
          Parser / Normalizer
                  ↓
             LifeEvent Store
                  ↓
     Timeline / Dashboard / Daily Summary
                                 ↓
                          Morning Briefing
```

UI는 ViewModel과 Repository를 통해 저장 데이터를 조회한다. Dashboard는 데이터를 생성하는 계층이 아니다.

## 2. 선행 데이터 설계

Phase 1에서 다음 계약을 확정하고 검증한다. 상세 주의사항은 개발 참고 문서에 유지한다.

- 5개 기본 테이블: raw_event, life_event, event_tag, event_entity, daily_summary.
- 원본 식별자, 원본 버전, 내용 해시, 정규화 이벤트 식별자를 구분한다.
- Raw 변경 이력 보존과 완전히 동일한 데이터의 재수집 중복 방지를 함께 설계한다.
- LifeEvent 갱신 시 id와 createdAt을 유지한다.
- Raw 저장 후 정규화 전에 프로세스가 종료되어도 재처리할 수 있게 한다.
- 하나의 Raw에서 여러 LifeEvent가 생성될 수 있으므로 하위 이벤트 식별 규칙을 둔다.
- 시각은 epoch milliseconds로 저장하고 원본 시간대와 종일 날짜 의미를 보존한다.
- JSON 스키마 버전과 파서 버전을 추적한다.
- 원본 기반 이벤트와 STEP_SUMMARY, BRIEFING 같은 파생 이벤트를 구분한다.
- 미수집·권한 없음·실패와 실제 값 0을 구분한다.

## 4. 검증 전략

| 검증 계층 | 핵심 대상 |
|---|---|
| 단위 테스트 | 파서, 식별 규칙, 날짜 경계, 집계, 브리핑 |
| Room 통합 테스트 | 중복 방지, Raw 보존, 재처리, 트랜잭션, 마이그레이션 |
| UI 검증 | 날짜별 정렬, 필터, 상세 이동, 빈 상태, 권한 및 오류 상태 |
| 실기기 검증 | 실제 소스 수집, 권한 철회, 재부팅, 백그라운드, 재연결 |

각 단계의 완료 체크는 해당 기준의 증거가 있을 때만 한다. 파괴적 DB 초기화를 정상 마이그레이션 대신 사용하지 않는다.

## 5. 최초 구현 묶음

준비 단계와 Phase 1부터 순서대로 구현했고 Phase 8까지 기능을 연결했다.

목표: 테스트 Raw 저장 → LifeEvent 정규화 → Timeline 확인 → 재실행 및 재처리 검증.

Calendar, NotificationListener, Health Connect를 이 기반에 연결했다. 기능 우선 구현은 완료했고, 개인 실기기 대조 및 장기 백그라운드 검증은 별도 확인이 필요하다. 디자인은 사용자 요청대로 후속 작업으로 남겼다.
